# Decision Log

Non-trivial implementation decisions and deviations from IU-MASTER-001 suggestions (spec §16 permits these; each is recorded here).

| # | Decision | Rationale |
|---|---|---|
| D-01 | Next.js 16 App Router, React 19.3, TypeScript strict, npm. | Spec default stack; npm is universally available (no lockfile existed). |
| D-02 | TypeScript pinned to 6.0.3, not 7.x. | TS 7 is the native (Go) port; Next's type-check and typescript-eslint use the JS compiler API. 6.0 is the stable JS-API line. |
| D-03 | CSS Modules + global design tokens (custom properties), no Tailwind. | Spec allows "Tailwind or token-based CSS". The design is bespoke (masks, glass, cinematic gradients); modules keep markup semantic and styles co-located. |
| D-04 | Fonts: Sora (display), Manrope (body), JetBrains Mono (labels) — OFL, self-hosted woff2 copied from `@fontsource-variable/*`, loaded with `next/font/local`. | Spec-suggested pairing; offline-deterministic builds; licences shipped beside files. |
| D-05 | One fixed, pointer-transparent canvas in the root layout; all interaction via DOM. | Spec §6.1 persistent canvas; guarantees keyboard/screen-reader/no-WebGL parity. |
| D-06 | Native scroll only; camera pulls `scrollY` per frame; ScrollTrigger for DOM reveals; ScrollToPlugin for anchor travel. No Lenis. | Spec §6.1 "prefer native scroll"; one scroll source. |
| D-07 | Camera = damped path parameter over a Catmull-Rom station path with dwell easing, plus lens shift (`setViewOffset`) for off-centre framing per aspect class. | Keeps subjects composed beside DOM copy without changing perspective; damping in path space prevents clipping through geometry. |
| D-08 | Project cards: poster by default, live 3D mini-world on hover/focus/transition, composited from an FBO with a rounded-rect SDF mask. Card tilt applied in-scene (camera parallax), CSS tilt only in poster mode. | Avoids fixed-canvas/DOM scroll desync and draws real depth; one WebGL context. |
| D-09 | Hero type scale `clamp(3.1rem, 4.9vw, 7rem)` instead of suggested `6.8vw`; section titles ~`3.1vw`. | Reference headline spans ≈28–30% of width; spec says scales are suggestions to adjust with QA. |
| D-10 | Content as JSON in `src/content/data`, validated by zod at build; every record carries `verification.status` (`placeholder` / `owner_verified` / `public_verified`) and `source`. Copy authored verbatim in the owner's spec is `owner_verified` with source `IU-MASTER-001 §x`; anything drafted during engineering is `placeholder`. | Content swap without touching scene/layout code (spec §10.1); auditable provenance. |
| D-11 | Global content mode `NEXT_PUBLIC_CONTENT_MODE` (`DEMO_CONTENT` default). Non-public modes emit `noindex` and show a discreet "Preview content" indicator; a publication-gate test fails if `VERIFIED_PUBLIC` is set while any rendered record is `placeholder`. | Spec §10 deferred-content gate made executable. |
| D-12 | No contact email/phone/social URL is invented. Unconfigured channels render an honest "available after profile review" state; `/resume` explains deferral. | Spec §4.2, §10.2. |
| D-13 | Assistant runs a local deterministic demo provider (keyword retrieval over fixture knowledge, citations to fixture IDs, `mode: "demo"`). `/api/assistant` implements the contract and returns `503` with status `unavailable` until a provider is wired. | Spec §9.1: no paid calls, honest labeling; free-text input works *as a labeled demo*. |
| D-14 | Prelude only on first visit on desktop fine-pointer, CSS-timed (≤2.4 s) with JS early-dismiss; skipped on mobile, reduced motion and repeat visits. | Spec S0 + LCP budget on mobile. |
| D-15 | `react-hooks/immutability` is off **only** for `src/experience/**`. | R3F mutates three.js objects and per-frame state in `useFrame` by design; the rule stays on for all DOM/UI code. |
| D-16 | zod runs on the server/build only; the client receives plain TypeScript types (`lib/assistant/contracts.ts`), the API validates with `lib/assistant/request-schema.ts`. | zod's JIT probe uses `eval`, which the CSP (correctly) blocks in Firefox; it also keeps the validator out of the client bundle. |
| D-17 | The 3D enhancement starts after `load` + idle on desktop, and on touch devices only after the first scroll/tap (or 5 s quiet) + idle. Touch devices default to `lite`, or `balanced` with ≥ 8 cores and ≥ 6 GB (or memory unreported). | Mobile TBT fell from 7.2 s to 30 ms; content and LCP never wait for WebGL. |
| D-18 | Light count is constant (`WorldLights` always mounted, intensity by presence); programs are precompiled against a linear HalfFloat target while the world root is hidden. | three.js keys programs on light count and output colour space; this keeps programs at 49–51 and travel hitch-free. |
| D-19 | Static/fallback posters are rendered from the live scenes (`scripts/capture/posters.mjs`), served as WebP with 480/800 `srcset` variants; the hero poster is preloaded with high priority. | Spec §6.7 (fallback matches the 3D); no stock imagery; mobile never downloads desktop posters. |
| D-20 | Scroll reveals animate opacity only (never `visibility`), and same-page anchors are handled in the capture phase (`AppRuntime`). | Unrevealed content stays focusable for keyboard/AT; `next/link` otherwise swallowed hash navigation. |
| D-21 | `resolveTier` never lets a software renderer run WebGL unless the user explicitly picks a tier. | SwiftShader frames are unusable; headless CI deterministically tests the static experience. |
| D-22 | Sora ships latin only (latin-ext removed). | All copy is latin; −1 font file on the critical path. |
| D-23 | Ground layers: the camera path crosses three terrain layers between stations. Crossing points are solved on the path per aspect; a canvas veil rises from 1.4 units above the ground, the layer above is hidden under it, and pointer parallax may never take the camera within 0.35 of a visible ground. | Seen from below, terrain reads as a floating sheet; a dip through dark is the honest cinematic cut between worlds. Pure functions, unit-tested (0 at every station). |
| D-24 | Frosted glass: vendor-prefixed declarations come **before** standard ones. | Lightning CSS (Next's minifier) otherwise dropped the standard `backdrop-filter`, so Chromium/Firefox had no blur. Measured cost with blur on: ultra 93–120 fps, balanced 121–153 fps on the Intel iGPU. |
| D-25 | Journey moon sits on the right frame edge (partially cropped) instead of near centre. | It overlapped the right-aligned subtitle at 16:10/16:9; the reference crops it at the edge. At 4:3 it now falls just outside the frame. |
| D-26 | Large/duplicate evidence stays local: `docs/evidence/video/*.webm` (≈15 MB) and Lighthouse JSON (the HTML reports embed the same data) are git-ignored; screenshots are WebP. | Keeps clone size reasonable; every artifact is reproducible with the documented scripts. |
| D-27 | Core detail is tiered (`coreDetail`): seams, carriages, dial ticks and the outer shell on ultra/balanced; physical clearcoat + anisotropy on **ultra only**, standard materials elsewhere. | On ANGLE/D3D11 each program compiles lazily at first use; physical variants cost 260–420 ms each vs ~100 ms for standard. Balanced stalls fell 3,859 → 1,253 ms with no visible loss at that tier. |
| D-28 | GSAP scroll choreography and below-the-fold posters start only after first paint (`afterFirstPaint`, `DeferredImg`). | They were ~110 KB and ~1 s of throttled main thread before the mobile LCP; content stays visible without them; posters keep size/alt (no CLS) and have a `<noscript>` copy. |
| D-29 | Self-hosted fonts are subset (Latin-1, punctuation, arrows; kern/mark/ccmp/locl) by `scripts/fonts/subset-fonts.py`. | 99 → 67 KB on the critical path; no Reserved Font Names in the OFL licences; CSS uses no OpenType features. |
| D-30 | `experimental.inlineCss` evaluated and **rejected**. | Measured slightly worse (mobile home LCP 3.1 → 3.2 s, case study 2.8 → 2.9 s, TBT up). |
| D-31 | `scrollbar-gutter: stable` on `html`. | Streamed first paint before the page scrolls made classic scrollbars appear mid-load and shift `vw` boxes (CLS 0.23 seen on desktop). |
| D-32 | Journey moon placement derives from the viewport aspect (`journeyMoonFor`). | Keeps the approved 16:10 screen position at 4:3 → 21:9 (it was off-frame at 4:3). |
| D-33 | Motion tokens in `src/lib/motion.ts` mirror the CSS `--ease-*`/`--d-*` tokens. | One timing vocabulary (enter / travel / commit) across CSS, GSAP and WebGL. |

| D-34 | Personal media enter through a pipeline, not by hand: `scripts/media/process-media.py` turns the owner's originals (git-ignored `media-src/`) into AVIF/WebP/JPEG portrait sizes, a 1080p remux + 720p H.264/AAC reel, poster and thumbnail, and writes `src/assets/media.json`; every output is re-encoded from fresh buffers or remuxed with metadata dropped. MP4/H.264 only. | Reproducible, metadata-safe (no EXIF/GPS), components never build media paths. H.264 plays in every target engine — verified with real playback in Chromium, Firefox and WebKit — so a WebM copy (+2.5 MB) bought nothing. |
| D-35 | Media copy is content: `src/content/data/media.json` holds the portrait description, reel labels, transcript cues, an on-screen description and an AI-provenance flag (zod-validated). The transcript and the AI disclosure are `placeholder` until the owner confirms them; the WebVTT captions are generated at build from the same cues (`/media/captions/[track]`). | Captions, on-page transcript and publication gate share one source; machine transcription and inferred provenance are never presented as verified. |
| D-36 | Placement: the portrait lives in the identity band (right column, the subject looking back across the statement); the hero gets only a quiet "Watch the introduction" chip under the CTAs; `/about` leads with the portrait (priority) and omits it from its identity band. | The hero stays the universe's (the core is the approved focal point); the human appears at the next beat; no repetition on one page. |
| D-37 | The reel player is a native modal `<dialog>` in a lazily loaded chunk mounted after first paint. Triggers open it synchronously inside the click (so playback with sound starts within the gesture); poster and video bytes are requested only on open; reduced motion opens on the poster; Save-Data drops the 1080p source. | Zero cost on the critical path; reliable autoplay-on-request (Safari requires the gesture); poster-first loading. |
| D-38 | Nothing overlays the film while it plays: captions sit in a reserved rail under the frame and the controls below that. Captions default to on (choice remembered). | The reel carries its own typography; the first iteration's overlaid captions and controls covered its closing name card. With the rail, captions cost nothing visually. |
| D-39 | While a full-screen media overlay is open the R3F loop switches to `frameloop="demand"` (store flag `mediaOverlay`). | The world is hidden behind a blurred backdrop: the GPU goes to video decoding; measured 0 WebGL draw calls during playback (GPU E2E). |
| D-40 | `CanvasBoundary` wraps the WebGL layer: a renderer that throws (e.g. re-created on a lost context) marks WebGL `failed` and the posters stay. | Found in this phase: without it the error reached `global-error` and replaced the entire page ("Something went wrong") — reproduced in WebKit under load and by a deterministic E2E test. |
| D-41 | E2E: media flows run on the static tier; the WebKit project is limited to one worker. Media + live 3D is covered on the real GPU suite. | Headless WebKit on Windows renders WebGL and decodes video on the CPU; parallel WebKit pages starved each other (lost contexts, stalled actionability) and made unrelated tests flaky. |
| D-42 | The résumé is the owner's PDF, copied byte-for-byte (`scripts/resume/import-resume.mjs`, SHA-256 checked) to one public URL that every résumé action uses; **View** opens it in the browser's own PDF viewer in a new tab, **Download** uses `<a download>`. No embedded viewer, no PDF library. | The site's headers forbid framing (`X-Frame-Options: DENY`, `frame-ancestors 'none'`, `object-src 'none'`); Chromium's viewer and Firefox's pdf.js render the PDF under those headers, so loosening them bought nothing. |
| D-43 | CV links are wired only where an existing record expects them (LinkedIn, GitHub, email, résumé); everything else (6 project repositories, 9 certificates, the phone with `publicDisplay: false`) goes to the unrendered, validated registry `verified-links.json`. | Content freeze: the temporary CV is a document, not a content source; no repository matched an existing project, and the phone is not authorised for display. |
| D-44 | `*.pdf binary` in `.gitattributes`. | `* text=auto eol=lf` could otherwise normalise line endings inside a PDF git judged to be text, breaking byte-for-byte integrity. |
